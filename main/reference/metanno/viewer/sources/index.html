    metanno.viewer.sources

    Read connections and table locations from metanno.yaml for the explorer and Copy code

    QueryError [source]

    Bases: RuntimeError

    A source could not be opened or queried

    SourceCatalog [source]

    Share lazily opened Ibis connections across the sources listed in metanno.yaml

    connection [source]

    Open a connection from metanno.yaml once, with cleanup controlled by its factory or this catalogue

    A Spark session stopped by the cluster, e.g. when YARN client mode loses its connection after the 2 hour TCP limit, is closed and opened again with its tables

    close [source]

    Close the connections opened by this catalog, a factory backend is closed only when it is a context manager

    list_sources [source]

    Describe each source for the sidebar: its default connection, the ones it can switch to, and whether it is a databases source that the sidebar expands with list_databases

    source [source]

    Return the SourceConfig of a source of metanno.yaml or of a database found by list_databases

    resolve_path [source]

    Find the source and table of a dataset given by its location, eg opened from an HDFS file browser extension

    The dataset is a table of the deepest file source of metanno.yaml that contains it and can use the connection. Otherwise the folder of the dataset becomes a source, read with the connection or default_connection

    RETURNS DESCRIPTION
    tuple[str, str, str]

    Source name, table name and connection, eg ("hdfs:///user/me", "runs/notes", "duckdb")

    list_databases [source]

    List the databases of a databases source, each becoming a source the sidebar shows under it

    When the backend has catalogs, e.g. Trino, the databases of every catalog are named catalog.database, and only those with a table the user can see are kept

    set_connection [source]

    Make connection the default of a source, in memory and in metanno.yaml, keeping the comments of the file

    list_tables [source]

    List the tables of a catalogue source, or the datasets and subfolders of a folder of a file source

    Each entry is a table or a folder named by its path under the source uri, eg runs/notes, which the sidebar passes back as folder to list that folder. A file source whose uri is one dataset has a single table named after its folder

    file_entries [source]

    Map the datasets and subfolders of a folder of a file source to "table" or "folder", eg {"runs/notes": "table"}

    Each subfolder is listed to tell a dataset from a folder of datasets, in parallel since listings do not query the connection. A connection with only list_folders gives no files, so its subfolders are tables

    file_table [source]

    Return the location and format of a table of a file source, for table and Copy code

    table_name is the path of the dataset under the source uri, or the name of the source folder when it is one dataset. A dataset is read as Delta when its folder has a _delta_log, as CSV when its data files are .csv files, as Parquet otherwise, unless metanno.yaml gives the format

    table [source]

    Return an Ibis Table from the source definition, reusing file registrations between queries

    connection is one of the source connections, its default one when None

    is_remote [source]

    Say whether a location is listed through the connection, eg hdfs://, s3a:// or gs://, rather than a local path

    resolve_uri [source]

    Return the location of a file source folder, a local path starts from the metanno.yaml directory when relative, a file:// uri becomes a path

    storage_entries [source]

    List a folder of a file source as (name, is_folder) pairs, for SourceCatalog.file_entries and file_table

    Remote folders, eg on HDFS or S3, are listed by the connection, with its list_storage method or the Hadoop filesystem of a Spark connection, local ones with pathlib. A connection with only list_folders gives the subfolders

    is_dataset [source]

    Say whether a folder, from its storage_entries, is itself one dataset rather than a folder of datasets and folders

    A Delta log, a Spark _SUCCESS marker or hive partition folders, eg year=2024, make a dataset, and so do data files, eg part-00000.parquet or 000000_0, without subfolders. Next to subfolders, .parquet and .csv files are tables of their own, see SourceCatalog.file_entries

    file_format [source]

    Format of a data file from its extension, eg "csv" for part-00000.csv.gz, None for a file without a known one

    opens_as_table [source]

    Say whether a location is a dataset or a .parquet or .csv file of its own, for SourceCatalog.resolve_path

    place [source]

    Key to compare locations, an HDFS uri without its host, eg hdfs://namenode/user/me is hdfs:///user/me

    checked_path [source]

    Return a table or folder path of a file source, refusing paths that leave the source folder, eg ../other

    catalog_databases [source]

    List the databases of a catalog that hold at least one table the user can see, for SourceCatalog.list_databases

    One information_schema query per catalog is much faster than a list_tables per database, e.g. 47 s instead of 6 min on the EDS Trino. A backend without information_schema, e.g. Spark, lists all the databases of the catalog
